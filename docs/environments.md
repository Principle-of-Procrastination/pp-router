健康检查成功表示网关和数据库可访问。`providers` 中的 `true` 仅表示配置了对应凭证，不证明供应商账户额度、具体模型可用性或供应商实时健康。

## 账号和凭证由谁提供

| 凭证 | 本地获取方式 | 团队服务器获取方式 |
|---|---|---|
| 管理员账号 | `make init` 首次生成，默认用户名 `pp_admin` | 由部署负责人提供；不要交付客户 |
| 公司应用调用密钥 | 初始化的演示密钥，或管理端“签发凭证” | 为目标公司、应用和环境单独签发 |
| 内部开户凭证 | 首次初始化生成，或管理员签发 | 由网关负责人配置到受信任的开户后台 |
| DeepSeek / Kimi 上游密钥 | 仅配置在后端 `.env` | 仅由运维维护服务器受保护的配置文件 |

本地首次初始化文件为 `.local/credentials.json`。当前服务器首次部署时，凭证加密取回到了**部署执行机**的 `.local/lighthouse-credentials.json`，其中 `admin.username` / `admin.password` 用于后台登录，`applications` 保存演示应用密钥。这些文件权限为 `0600`、被 Git 忽略，其他人克隆仓库不会得到它们；需要向部署负责人申请，不能从文档或 API 找回明文。

`make init` 不会重置已有密码或重新导出旧密钥。不要在共享服务器上删除数据库来“找回密码”；按 [运维手册](../deploy/README.md#凭证维护)处理。

## 环境隔离

本地和服务器使用独立数据库，账号密码、公司内部 ID、授权 ID、调用密钥和用量互不通用。把本地密钥换一个 API 地址不会自动变成服务器密钥。

密钥上的 `environment` 是**调用归因标签和工具续接隔离条件**，例如 `local`、`staging`、`production`。它不会切换网关地址、创建数据库、改变上游供应商或创建独立限流额度。初始演示密钥即使在服务器上运行，标签也仍是 `local`；正式接入应新建自己的公司应用密钥并明确环境。

## 当前部署记录

- Lighthouse：上海，实例 `lhins-pjwgqizk`，公网 IP `150.158.155.100`，升级后 4 核 / 4 GB / 60 GB。
- Docker Compose 项目：`pp-router`；常驻容器为 `gateway`、`web`。
- 发布入口：`/opt/pp-router/current`；持久化配置与数据：`/opt/pp-router/shared`。
- 后端端口只在容器网络内使用，公网由 Nginx 提供 HTTPS；证书续期 timer 为 `pp-router-cert-renew.timer`。
- 当前上线验收只消耗 640 token。详细范围和证据见 [验收记录](../specs/local-mvp/acceptance.md)。
